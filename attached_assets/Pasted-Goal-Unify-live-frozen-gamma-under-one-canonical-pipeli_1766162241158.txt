Goal

Unify live + frozen gamma under one canonical pipeline:

options chain → per-contract call/put GEX → per-strike aggregates → canonical totals (gross/net/call/put) + diagnostics → sanity gates → persist audit + DB → UI reads only

No UI-side math. No alternate snapshot construction paths.

Step 0 — Hard rule: one snapshot builder only

Action

Search for every place AuditSnapshot( is instantiated directly.

Replace all direct instantiations used for gamma with one function call:

snapshot_from_gamma_exposure_result(...) (or a single wrapper you create)

which MUST call compute_aggregate_gex() from app/core/gex.py

and MUST call build_audit_snapshot() from app/core/audit_snapshot.py

Acceptance

There is exactly one “gamma snapshot construction” function used by both:

live scheduler

freeze-at-close scheduler

Step 1 — Fix gamma_scheduler bypass (root cause you already found)

Action
In gamma_scheduler.py (or wherever the scheduler is):

Stop building AuditSnapshot(...) with only legacy fields (total_gex_abs, total_gex_net) and/or only net_gex_per_strike.

Ensure the scheduler receives/constructs per-strike structures that include:

call_gex

put_gex

net_gex (call - put)

and any “abs” value you use for ranking (should be gross magnitude per strike, not abs(net))

Then call:

aggregate = compute_aggregate_gex(strikes_data)

snapshot = build_audit_snapshot(..., aggregate=aggregate, strikes_data=strikes_data, diagnostics=diagnostics, ...)

Acceptance

call_gex_total, put_gex_total, gross_gex, net_gex are non-null in the saved audit JSON for every valid snapshot.

The UI no longer displays 0.000B due to missing fields.

Step 2 — Guarantee call/put separation at the source

Action
In the per-contract calculation stage (often in something like options_gamma.py / calculators.py):

Compute call_gex and put_gex independently per contract.

Store put gex as positive magnitude.

Compute net at aggregation time: net = call - put

Compute gross at aggregation time: gross = call + put

Canonical convention

call_gex >= 0

put_gex >= 0 (magnitude)

net_gex = call_gex - put_gex (signed)

gross_gex = call_gex + put_gex (magnitude)

Invariant: gross_gex >= abs(net_gex)

Acceptance

Per-strike data includes both call and put components; you never “lose” separation by netting OI first.

Diagnostics no longer show None when present in the audit JSON.

Step 4 — Fix unit scaling once and only once (the “0.000B” bug)

Action
Decide on one storage unit for all snapshots and enforce it:

Recommended

Store all GEX values in raw numeric units (whatever your canonical functions output).

Store gex_units metadata in snapshot (string), e.g.:

"raw" or "dollar_gex" or "oi_gamma_units"

UI formatting chooses how to display:

If values are already in billions, UI must NOT divide by 1e9.

If values are raw and large, UI can divide by 1e9 for display.

Concrete fix

Remove any UI formatting that does gex/1e9 unless you confirm the stored values are raw-not-billions.

Implement a single helper in UI: format_gex(value, units_meta).

Acceptance

Audit JSON shows non-zero gross_gex/net_gex, and UI shows consistent numbers that match audit JSON (within formatting).

Step 5 — Sanity gates must block DB writes but still persist audit

Action
Keep current behavior:

If sanity fails, write audit JSON always

But skip DB/model ingestion for that snapshot

Update sanity gate logic for RUT:

Your log shows GATE2_GEX_CONCENTRATION: Top strike has 100% of total GEX.

That can be caused by:

chain truncation too aggressive (only one strike survives)

OI missing/zero except one strike

strike bucketing/rounding collapsing many strikes into one

So:

Add a “pre-gate explanation” field to the audit snapshot:

strike_count, nonzero_strike_count, top_strike_share, truncation_reason

If strike_count < N_min (e.g., < 30) mark snapshot invalid with explicit reason: CHAIN_TOO_THIN.

Acceptance

Invalid RUT snapshots explain why (thin chain vs true concentration).

Step 6 — Freeze-at-close must use the same snapshot pipeline

Action
Implement freeze as a scheduler event that:

captures a final chain snapshot at close window

runs the same canonical pipeline (Steps 1–5)

writes to:

logs/audit/{symbol}/...json

logs/frozen/{symbol}/{date}.json (or DB “frozen” table)

UI “Frozen” tab reads frozen snapshot record; UI does not recompute.

Acceptance

Frozen snapshots have the same fields as live snapshots.

Frozen tab never shows zeros unless snapshot itself is truly zero.

Step 7 — Add two invariants to automated tests (prevents regressions)

Action
Add tests (or extend existing) that assert:

gross_gex >= abs(net_gex) always

gross_gex == call_gex_total + put_gex_total

net_gex == call_gex_total - put_gex_total

strike_count >= min_strikes for “valid” snapshots

Acceptance

Tests fail immediately if anyone reintroduces netting-before-separating or UI-style scaling in backend.
